# Перенос профілів і growth loop

Цей шар робить Synera легше показувати і легше наповнювати без скрейпінгу чужих акаунтів.

## Що працює зараз

- У профілі є кнопка **Імпорт**. Людина вставляє власний текст профілю, CV, сайт або Synera JSON, підтверджує право на ці дані й отримує редаговане прев’ю.
- Імпорт заповнює лише існуючі публічні поля: ім’я, місто, "можу допомогти", "шукаю". Він не зберігає email, телефон, токени, щоденник, приватні нотатки чи зовнішній account id.
- У профілі є кнопка **Картка** / **Поділитися**. Вона створює короткий текст для ручного пересилання і portable JSON для повторного імпорту в Synera.
- JSON завжди ставить `is_discoverable: false`, щоб новий або перенесений профіль не став публічним автоматично.
- Discover cards показують коротку підказку про можливу взаємну тему. Це локальна евристика за ключовими словами, не AI-рішення і не оцінка людини.

## Чому саме так

Автоматичне копіювання профілів із платформ типу LinkedIn має високий ризик бану і порушення умов. LinkedIn прямо забороняє software/scripts/robots для scraping/copying профілів і даних, а також unauthorized automated methods для контактів або engagement. Тому робочий шлях для MVP: користувач сам переносить свої дані або використовує офіційний експорт власних даних. LinkedIn Help також уточнює, що їхній download дає власні personal data, а не дані інших members.

Web Share API підходить як мобільний share loop, бо share target обирає сам користувач у системному вікні. На desktop або без підтримки браузера Synera падає назад на clipboard.

## Що це дає для віральності

Перший вірусний цикл має бути не "запроси 5 друзів", а корисний артефакт:

1. Я заповнюю профіль.
2. Synera показує, яку користь я шукаю і що можу дати.
3. Я копіюю картку і кидаю її конкретній людині.
4. Інша людина імпортує JSON або повторює структуру.
5. Discover/meeting request дає наступну дію всередині продукту.

Після публічного HTTPS-хоста картка автоматично зможе містити справжній Synera URL. На localhost URL не додається.

## Наступні кроки

| Пріоритет | Робота | Навіщо |
| --- | --- | --- |
| A | Відновити Supabase Auth/REST і опублікувати HTTPS | Share card має вести в реальний продукт, не в локальне демо |
| B | Додати офіційний CSV/vCard import для власних даних | Менше ручного paste, але без скрейпінгу платформ |
| C | Додати public profile slug з окремою таблицею consent | Справжні посилання на профілі, QR і referral attribution |
| D | Додати abuse/report/block/deletion | Перед реальними користувачами |
