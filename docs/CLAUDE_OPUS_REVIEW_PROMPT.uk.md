Перевір **Synera** й дай незалежний висновок про готовність до обмеженого пілота. Мета продукту — реальна взаємовигідна співпраця двох людей: від профілів і узгоджених умов до результату, прийнятого отримувачем. Знайди найцінніші наступні кроки, не переписуй продукт заради нового дизайну.

Репозиторій: https://github.com/AndriiEagle/synera_-MVPplus-
Гілка: **main**. Зафіксуй SHA перед початком.

1. Прочитай `README.md`, `docs/PRODUCT_DNA.uk.md`, `docs/REVIEW_HANDOFF.uk.md`, `docs/quality/reviewed-release-20261015.uk.md`.
2. Звір `git rev-parse HEAD`, `git status --short` і дві перевірки ancestry з handoff. Review має включати source `76e189756f807cf8a6cf553cc687c626ac16ffff` та історію `6642c89359969afade480a7140e7feed08ad9574`. Якщо їх немає — назви точний SHA і відсутнє; не оцінюй стару копію як нову.
3. Назви OS, Node, доступні browser engines і PostgreSQL. Виконай релевантні команди handoff. Пропуск або відсутній runtime не є PASS; не підміняй живу перевірку fixture.
4. Перевір source і реальні екрани самостійно. Авторські звіти — джерело гіпотез; непов’язаний із перевіркою claim лишається непідтвердженим.

Обов’язкові інваріанти: Current default, добровільні Atelier/«Нічна карта», обидві незалежні згоди, revision invalidation, receiver-only acceptance, CAS, приватність після logout, незбережені чернетки, явний retry без дублювання, власні слова людини без перекладу, працездатна мова/навігація при denied localStorage. API, приватні дані, config і query URL не входять до публічного SW cache. Не роби невидимі consent/gate послаблення заради зеленого сценарію.

Перевір насамперед:

- Двох незалежних акторів: профіль → редакція → дві згоди → запрошення → прийняття → чат → місце → доказ → receiver acceptance. Відмови сервера, скасування, stale response, logout і повтор доставки — частина шляху.
- SQL/RLS на справжній одноразовій локальній БД: дії виконують самі актори як `authenticated`, не owner-seed. Після кожної міграції чинний `stack-invariants` має лишатися зеленим. Production rows не читай і production SQL не застосовуй.
- Дизайн через screenshots і кліки: 320/390 px, великий екран, keyboard/focus, enlarged text, Current/Atelier, loading/error/empty. Шапка не перекриває статус чи вхід; людина може вийти з добровільного стилю. Фізичні телефони й WebKit — окремі gates.
- Кожний зелений browser сценарій: чи не пропущено крок, чи fixture не відмовила, чи видно очікуваний результат. Перевір повернення мови зі свіжим екраном; візьми власний текст, схожий на підпис («Оновити») або на зібрану фразу.
- Preview/build відтворюються без прихованої локальної папки чи секрету. Asset hashes звірені; build не означає deployment.

Відкриті launch gates — у handoff: production/recovery/точний rollout, signed JWT і дві живі сесії, фізичні Android/iPhone, account deletion/room retention. Provider-функції та юридичні тексти мають окремі межі. Не приймай старий HTTP readback за сьогоднішній. Старі planning snapshots і premium branch не є актуальною реалізацією; потрібний premium-дизайн уже перенесено в поточний перемикач.

Це завдання на **незалежні висновки**. Не змінюй production, доступи, видимість repo, secrets, billing; не надсилай повідомлень людям і не запускай оплачувані моделі. Зовнішній spend cap цього review — $0. Попередня provider-хвиля має невизначену вартість і лишається HOLD до canonical reconciliation; не перезапускай її.

Якщо власник окремо замовив виправлення: одна відтворена пріоритетна проблема → інваріант → RED на старому коді → вузький fix → GREEN → негативна/mutation-перевірка. Збережи чужу роботу, додай лише власні файли, поверни окрему гілку `codex/<task>` і commit/PR із командами перевірки. Ніякого force-push, автоматичного merge або deploy. Зміна default дизайну чи продуктової семантики потребує рішення власника. Не повторюй незмінені повні набори заради кількості запусків.

Поверни українською компактний звіт:

- SHA й середовище; що самостійно перевірив і що лишилося неперевіреним.
- До п’яти найважливіших P0/P1/P2: факт → file/line → кроки відтворення → вплив → потрібне виправлення.
- Де попередні твердження не підтвердилися; жодних вигаданих відсотків готовності.
- Чи можна запросити перших людей зараз, із конкретними доказами й межами.
- Один найцінніший наступний крок на 5–20 хвилин; окремо перелік довших зовнішніх gates.
