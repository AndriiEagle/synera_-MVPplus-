# LIVEOPS: чинний продукт на наявному пілоті

Ціль: **Cloudflare Pages `synera-pilot` → Neon `quiet-credit-94155104`, production,
neondb, AWS us-east-2**, власні акаунти двох людей, збереження профілю та справ,
Google-вхід. Нових проєктів чи залежностей цей інструмент не створює.

**Локальна реалізація готова до перевірки власником; живе підключення не виконане.**
У цій лінії файл із ключами не читався. Автоматичний Direct Upload має чесну
межу: `deploy` повертає `MANUAL_REQUIRED` і точний ZIP-крок. Тому `all` **не обіцяє
повністю автоматичного релізу**: виконує інспекцію, міграцію й admission, а потім
зупиняється перед ручним завантаженням. Результат SQL до цієї зупинки вже може
бути збережений. Після будь-якої зміни environment потрібен новий deployment.

## Перед живою командою

1. Збережи попередній production deployment ID та приватний знімок environment.
   Neon backup/recovery і restore в disposable branch мають бути перевірені
   власником за CHECKLIST deploy-kit. Інструмент не видає свій SQL-тест за restore.
2. Закрий нові входи на час SQL: у **поточному** deployment
   `SYNERA_REGISTRATION_ENABLED=false`, Google/open registration=false. Якщо
   змінив налаштування — спочатку активуй їх новим deployment. CLI не доводить,
   що старі вкладки/сесії вже закриті.
3. Pages → synera-pilot → Settings → Bindings: має існувати KV binding
   **`SYNERA_LOCATION_EPHEMERAL`** до наявного відповідного KV namespace. Без нього
   поточний Worker відхиляє OTP; `flags closed` зупиниться `OTP_KV_REQUIRED`.
   Якщо namespace відсутній, власник створює його через Cloudflare Storage &
   databases → KV, прив'язує назвою вище та перевіряє тариф/ліміти. Pages:Edit не
   означає право створювати KV; CLI не створює його приховано.
4. Наявний Pages `SYNERA_NEON_DATA_URL` має відповідати production Auth URL.
   `env set` читає Auth integration через API, перевіряє пару наявним
   `neonEndpoints`; відсутній/інший Data API URL → HOLD. Нічого не вгадується.
5. `secret set` зберігає наявний Pages `OPENROUTER_API_KEY` без читання його
   значення. Якщо його немає, потрібен окремо підготовлений ключ у тому самому
   `.env.local` як `OPENROUTER_API_KEY=`; ці п'ять рядків не можуть створити ключ
   OpenRouter. Без ключа secret-крок — HOLD. **Live AI залишається OFF**, платних
   model calls ця команда не робить. Два локальні випадкові секрети інструмент
   один раз додає в `.env.local` як `SYNERA_LIVE_AI_HMAC_SECRET=` та
   `SYNERA_OPERATOR_TOKEN=`. Значення ніде більше локально не записуються.

## Команди з кореня цього checkout

```powershell
node tools/pilot-ops.mjs all --dry-run
node tools/pilot-ops.mjs all
```

Dry-run показує план усіх API-кроків із прихованими payload/адресами, включно з
кроками після ручної паузи. Він **не читає `.env.local`, не генерує секретів,
не надсилає жодного запиту, не виконує SQL і не означає PASS пілота**.

Живий `all`: `inspect → migrate → member add` для кожної адреси → `deploy`.
Міграції пакуються одним упорядкованим HTTP batch у транзакцію; `BEGIN/COMMIT`
з kit замінює серверна batch-транзакція. Окремий read-only catalog acceptance
закінчується `ROLLBACK`. Помилка припиняє наступні кроки. Disposable fixture
`11-acceptance-disposable.sql` **ніколи не запускається на production**.

На `MANUAL_REQUIRED`:

1. Cloudflare → Workers & Pages → **synera-pilot** → Create deployment →
   **Production → Direct Upload**. Завантаж ZIP з
   `docs/deploy-kit-20261029/liveops/`, назву й SHA дивись у квитанції та
   `manifest.json`. Вибери саме ZIP з `_worker.js`, не всю теку з SQL/docs.
   Advanced-mode `_worker.js` зберігається. Deploy; звір `/release.json`.
2. Виконай налаштування нижче. Вони ідемпотентні за результатом; повторний PATCH
   секрету з тим самим значенням допустимий. Нові випадкові значення не
   генеруються повторно. `env set` навмисно закриває readiness до наступних кроків.

```powershell
node tools/pilot-ops.mjs env set
node tools/pilot-ops.mjs secret set
node tools/pilot-ops.mjs google
node tools/pilot-ops.mjs flags closed
node tools/pilot-ops.mjs flags google
```

3. Збережи точний Neon Provider callback у Google Cloud, перевір trusted origin,
   test users та KV binding. **Повтори ручний Production Direct Upload того
   самого ZIP**, щоб нові vars/secrets/flags діяли в Worker. Потім:

```powershell
node tools/pilot-ops.mjs smoke
```

`smoke` звіряє файли `/release.json` з kit, `/config.json`, health із
`X-Synera-Client: 1`, проходить **тільки редиректи** Synera → Neon → Google,
звіряє client ID і не відкриває accounts.google.com. Потім запитує один OTP
на першу адресу. `sent:true` підтверджує прийняття запиту, не доставку листа чи
вхід. Локальна резервація забороняє повторне OTP-навантаження протягом 15 хв;
серверні ліміти можуть відхилити запит раніше. Повторний smoke у цьому вікні
повертає `HOLD_OTP_RATE_LIMIT`. Згоди під час реального входу кожен дає сам.

Окремі команди:

```powershell
node tools/pilot-ops.mjs inspect
node tools/pilot-ops.mjs migrate
node tools/pilot-ops.mjs member add partner@example.com
node tools/pilot-ops.mjs member remove partner@example.com
node tools/pilot-ops.mjs flags open
```

`inspect` друкує catalog inventory в receipt JSON: відсутні нові об'єкти
допустимі, відсутня база r8, невідомі function bodies, невідповідний API role або
форма відповіді або частково наявна нова міграція — HOLD. Міграційний guard додатково перевіряє partial state та
визначення policies **до commit**. `flags closed` повторно перевіряє фінальний
catalog, щоб не відкрити ще не мігровану базу. Інспекція не є аудитом усіх
довільних об'єктів production.

`member remove` прибирає **тільки SQL admission**, не акаунт/профіль/історію чи
provider session. Потім власник прибирає цю адресу із `SYNERA_PILOT_EMAILS`,
виконує `flags closed` (і за потреби `flags google`) та redeploy. Не видаляй
адресу власника помилково; live-revocation чужих сесій тут не підтверджена.

`flags open` зараз відмовляє **до мережевого запиту**: усі п'ять чинних
`config/privacy-readiness.json` requirements мають бути true. CLI не змінює їх
і не підписує юридичне/live-приймання замість власника. Порядок прапорців із
[OPEN-REGISTRATION](OPEN-REGISTRATION-20261029.uk.md) збережений.

Кожен запуск друкує JSON і пише квитанцію в
`docs/pilot-ops-20261030/receipts/`. Там немає ключів, SQL із адресами, токенів
OAuth, URI бази, cookies чи тексту помилок провайдера. `HOLD`/`MANUAL_REQUIRED`
мають exit code 2. Timeout mutation → `OUTCOME_UNKNOWN_NO_AUTOMATIC_RETRY`:
спочатку звір стан провайдера, не запускай сліпий повтор. Lock не дозволяє
одночасні живі команди з цього checkout. Якщо процес аварійно завершився,
переконайся, що він уже не працює, звір невідому дію й тільки тоді прибери
застарілий `receipts/pilot-ops.lock`. Він не містить секретів.

## Що зробити на двох телефонах

Андрій і партнер окремо відкривають `https://synera-pilot.pages.dev`, оновлюють
стару PWA/вкладку й бачать чинний темний із золотим продукт. Кожен читає
повідомлення про дані, сам дає обидві згоди, входить власним Google-акаунтом
(або власним email-кодом), зберігає профіль і перезавантажує сторінку. Профіль
має лишитися своїм після повторного входу/закриття вкладки.

Для спільного проходу кожен окремо дозволяє видимість профілю. У реальному
шляху: конкретні умови → дві незалежні згоди на ту саму версію → запрошення
на зустріч → прийняття адресатом → малий справжній результат → прийняття
одержувачем. Автор не приймає за партнера. Перезавантажити обидва телефони:
умови, згоди та результат збереглися; вихід на A не змінює особу B; без входу
чужі приватні дані недоступні. **До цього `LIVE_TWO_PERSON=HOLD`**, навіть якщо
smoke зелений. GPS, rooms, erasure та live AI цим сценарієм не відкриваються.

## Перевірені джерела та чесні межі

Контракти звірені 30.10.2026: [Neon OpenAPI](https://neon.com/api_spec/release/v2.json)
(`getConnectionURI`, branch Auth, OAuth providers, trusted domains),
[Neon serverless driver](https://neon.com/docs/serverless/serverless-driver),
[HTTP implementation](https://github.com/neondatabase/serverless/blob/main/src/http/index.ts),
[Cloudflare create deployment](https://developers.cloudflare.com/api/resources/pages/subresources/projects/subresources/deployments/methods/create/),
[офіційний Wrangler secret PATCH](https://github.com/cloudflare/workers-sdk/blob/main/packages/wrangler/src/pages/secret/index.ts).
Локальні SHA та operation locators —
[`api-contracts.json`](pilot-ops-20261030/api-contracts.json).

Без токенів не перевірені: права акаунтів, точна live-схема/ролі, HTTP SQL
на production, backup/restore, KV binding, активні Pages settings, точний Neon
provider callback, Google consent screen, доставка OTP, sign-in, persistence і
ізоляція реальних акаунтів. Fake fetch перевіряє контракт та відмови, не ці
живі властивості. Новий провайдерний endpoint чи Cloudflare asset API не
вигадувався. Нічого не встановлено, не закомічено, не запушено й не розгорнуто.

Локальне приймання: **19 тестів pilot-ops + 3 незмінені Google-smoke = 22 PASS**;
основний Node/PWA/i18n/Neon/kit набір — 896 PASS, 1 умовний PostgreSQL skip.
Повний Playwright прогін: 155 PASS і одна відмова старого F3 fixture. У fixture
додані два чинні Google config-поля, без послаблення assertions; цей сценарій
окремо повторно PASS. Повний набір після зміни тільки fixture не повторювався.
Header, offline shell, a11y, обидва bundle scans і шість інших browser acceptance
скриптів — PASS. `flags open --dry-run` — exit 2, calls=[]; mutation-тест
спростовує знятий privacy-gate. Команди, hashes і межі —
[`verification.json`](pilot-ops-20261030/verification.json).
