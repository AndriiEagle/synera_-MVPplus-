## Жорстка межа $3/день і квитанції

**Сам KV не є достатнім засобом для жорсткого concurrent cap:** незалежні Worker isolates можуть
одночасно прочитати старий баланс. Тому admission/reservation серіалізує один Durable Object на UTC-день,
а існуючий KV зберігає лічильники й JSONL-проєкції. Це вузький компонент пілотного Worker, не новий
fleet-router/ledger. Не підміняй його локальним mutex або read/modify/write у KV.

Перед кожним generation: перевірка `/api/v1/key` (`0 < limit <= 3`, `limit_reset=daily`, є залишок),
свіжий `/models`, provider price ceilings через `max_price`, durable reservation за консервативною
UTF-8 byte-bound оцінкою input + template overhead + 600 output. `charged + reserved + next > cap`
повертає 503 `live_ai_cap_reached` до платного POST. Cap можна зменшити, значення понад 3 відхиляються.
Резерв не повертається при невизначеному outcome/перезапуску. При справжньому usage/cost списується
сума з OpenRouter; за відсутнього usage/cost або transport timeout — весь резерв, `costStatus=cost_unknown`.
Якщо фактична сума перевищила цінову межу, об’єкт зупиняє наступні запити до перевірки власником.
Захист припускає дотримання OpenRouter заявлених цін, output bound і key limit; реальне виконання
та затримка білінгу ще не перевірені. $3 — inference-бюджет OpenRouter, не тариф Cloudflare.

Rate limit: 6 спроб/хв і 60/UTC-день на денний HMAC connection IP, консервативно спільний для NAT.
Сирий IP не зберігається. KV rate shards TTL=120 s, authoritative HMAC counts до 3 діб, receipts/totals
до 90 днів. DO alarm прибирає rate keys, пізніше решту. Шардовані ключі не перевищують KV write-rate
одного ключа й не гублять append при паралельності:

```text
live-ai:YYYY-MM-DD:receipt:UUID  # один JSON line без тексту
live-ai:YYYY-MM-DD:attempt:UUID  # reserved/pending до generation, для crash recovery
live-ai:YYYY-MM-DD:spend:UUID    # cumulative spend snapshot
live-ai:YYYY-MM-DD:rate:HMAC:UUID
```

`GET /api/ai/spend?day=YYYY-MM-DD[&cursor=UUID]` повертає charged/reserved/calls/halted та до 1000 receipts,
`nextCursor` для наступної сторінки. Імпорт до **наявного** fleet ledger робить Claude з дедуплікацією
за requestId/providerRequestId; це transport/cost evidence, не автоматичне приймання змісту.
`reservedUsd>0` після втрати Worker означає невирішену спробу, не нульову вартість; generation не повторювати.
Квитанція `costStatus=reserved, outcome=pending` записується **до** генерації: crash між
платним запитом і settle не залишає витрати без експортованого request ID. Завершення
додає окрему KV receipt line; DO-експорт повертає останній стан кожного ID. `calls` —
лічильник допущених спроб, не доказ, що кожна дісталася провайдера.

Spend і `GET /api/ai/health` мають однаковий `Authorization: Bearer <SYNERA_OPERATOR_TOKEN>` і no-store.
Важлива різниця бази: існуючий `/api/neon/health` використовує `neon-store.availability()` у продукті,
тож його публічний read-only контракт збережено. На цій базі він не мав operator auth; client-header
не використано як захист spend. Секрет оператора ніколи не повертається в config/browser.

   `limit_reset=daily` (UTC), без BYOK/автозаміни маршруту. Не використовуй спільний fleet key.
   Перевір значення у dashboard/`GET /api/v1/key`; прикладні перевірки не замінюють provider cap.
2. Перевір модель і фактичний endpoint у поточному каталозі OpenRouter. Скопіюй точний provider slug
   (включно з варіантом/регіоном за потреби), перевір ZDR, умови зберігання/навчання, субобробників,
   країни і правову підставу передачі. Цей slug стане `SYNERA_LIVE_AI_PROVIDER`: його бачить людина
   перед згодою; запит містить `provider.only: [slug]`. Зміна провайдера потребує нового перегляду notice.
   Непідтверджену країну не називай «Швейцарія» або «ЄС». Без прийнятого маршруту AI лишається OFF.
3. У Cloudflare Pages pilot → Settings → Variables/Secrets встанови **секрети**:
   `OPENROUTER_API_KEY`, випадковий `SYNERA_LIVE_AI_HMAC_SECRET` не коротший за 32 символи,
   випадковий `SYNERA_OPERATOR_TOKEN`. **Ніколи** не клади ключі у vars/TOML/git/config.json.
   Вони створюються/встановлюються власником; ця лінія їх не читала й не створювала.
4. Для hard cap підготуй окремий Durable Object Worker із `neon/live-ai-budget-worker.mjs`
   та прикладом `neon/wrangler.live-ai-budget.example.toml`. У прикладі заміни лише KV ID на
   **існуючий** `SYNERA_LOCATION_EPHEMERAL`. DO використовує SQLite. Приклад конфігурації —
   не виконаний deploy. Pages не може сам створити DO: власник розгортає coordinator Worker
   і в pilot Pages bindings додає `SYNERA_LIVE_AI_BUDGET` → `LiveAiBudget` цього Worker.
   Обидва Worker використовують той самий KV. У coordinator не потрібні OpenRouter/операторські ключі.
   Всі preview/production пілоту мають використовувати один budget namespace, не окремі ліміти.
5. Публічні vars пілоту: `SYNERA_LIVE_AI_MODEL=z-ai/glm-5.3-flash`,
   `SYNERA_LIVE_AI_DAILY_CAP_USD=3`, перевірений `SYNERA_LIVE_AI_PROVIDER`,
   `SYNERA_SITE_URL` = точний HTTPS origin. Спочатку `SYNERA_LIVE_AI_READY=false`.
   Після інтеграції/перевірки notice та bindings власник ставить `true` і розгортає перевірений build.
   Відсутня будь-яка обов’язкова залежність → config `liveAiReady:false`, перемикач прихований,
   на екрані чесна причина. Reachability зовнішніх сервісів перевіряється окремо, не цим прапорцем.
6. Claude після встановлення секретів запускає **один раз**, з `SYNERA_OPERATOR_TOKEN` у приватному
   process environment (не в командному рядку):

```powershell
node tools/live-ai-smoke.mjs --execute --origin=https://PILOT-HOST --receipt=tmp/live-ai-smoke.json
```

Smoke робить один синтетичний POST і друкує cost, tokens, model, request ID та input/output hashes.
`.attempt.json` резервується до POST і блокує повтор навіть після timeout. Missing cost/error → HOLD,
не повторюй generation; спочатку збери Worker spend/receipt для вже виконаної спроби. Файл квитанції
не містить ключа або відповіді. `PASS_TRANSPORT_AND_COST` не оцінює якість персонажа: Claude/Андрій
окремо читають AI-відповідь у Demo, перевіряють label, роль, one next step і відсутність реальних обіцянок.

Для відкату: `SYNERA_LIVE_AI_READY=false` у наступному дозволеному deployment; відкликати/disable ключ
у OpenRouter. Не стирай логи й namespace для обходу unresolved reservation. Model calls цієї лінії: 0.
