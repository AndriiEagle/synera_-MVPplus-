## Зміни та перевірки

**Локальний результат:** усі чотири HIGH (W1/R1/D1/R2) мають виправлення й перевірки, що відтворювали дефект до правки та проходять після неї. Це підготовлена лінія для review/merge, не підтвердження живого Neon або релізу.

- **W1:** обидва режими OTP проходять `withOtpProtection`; allowlist перевіряється раніше за KV/провайдера. Перевірено відсутню issuance, п'ять спроб, resend без скидання бюджету, ліміт надсилання та відмову без KV. KV залишається eventually consistent, не строгим глобальним лічильником. Навіть закритому пілоту тепер потрібний KV binding; інструкцію генератора kit оновлено.
- **R1:** `deleteProfile()` завершується 405 без мережевого DELETE; gateway також блокує цей метод. Кнопку прямого видалення приховано. Генератор Neon і `schema.proposal.sql` більше не дають DELETE/policy. Нова `profile-delete-guard.migration.sql` знімає стару policy і grant; застосування двічі до відтвореної старої схеми перевірене у disposable PG. SQL acceptance підтверджує збереження профілю й зустрічі іншої сторони. Історичний Supabase SQL не переписувався.
- **D1:** A→B скарга, тобто текст автора A, видаляється; B→A лишається з текстом B (`Safety evidence`). Target UUID стає стабільним загальним надгробком `00000000-0000-4000-8000-000000000000`. Знято тільки target FK, який інакше каскадував би скаргу при видаленні Auth. Trigger-only definer перевіряє нові targets без нових SELECT/EXECUTE прав клієнта. Перевірено нормальний новий report, відмову для вигаданого target/надгробка, повторне стирання, purge простроченого hold і збереження чинного. Строк 90 днів — **пропозиція для owner/legal**, не встановлений юридичний висновок; після його спливу потрібний щоденний purge. Розкриття меж додано uk/de/en до privacy centre та Privacy-by-Design.
- **R2:** guard уже був у правильному місці ORDER; цю властивість збережено. Kit перевіряє enabled trigger, правильну trigger function та BEFORE UPDATE ROW тип до location/address міграцій. `00-inspect.sql` заново згенеровано з поточного SQL; він містить явні `meeting_status_guard_ready` і `profiles_direct_delete_disabled`, pg_trigger, pg_policies, relforcerowsecurity, фактичні owner/API-role bypass ознаки та EXECUTE ACL включно з implicit PUBLIC. Вимкнений trigger тепер дає false, а не хибний green. Повний read-only файл виконався у disposable PostgreSQL.
- **W3:** location body читається потоком із byte cap 1024, скасуванням reader та UTF-8 validation. Oversized stream тест доводить, що залишок потоку не читається й RPC не викликається.
- **W4:** окрема дія `eraseCompleteApplicationData`, окремий config.json gate `completeErasureEnabled` від `SYNERA_COMPLETE_ERASURE_READY` та profile-erasure readiness, typed phrase `DELETE ALL`, expectedSubject і перевірка точного receipt. Невдалий/неповний результат не показується як успіх. Усі нові тексти uk/de/en; підтвердження очищається на виході. Код чесно повідомляє про provider deletion pending, чужі скарги, згадки й tombstone.
- **W2, часткова мітигація:** для обох erasure-дій `sessionRevoked=false` показує попередження та окрему доступну кнопку явного виходу поза прихованим workspace. Безумовного Set-Cookie у відкладеній відповіді erasure немає: він міг би стерти нову B-cookie. Автоматичне conditional clearing старої cookie й поведінка живого Auth залишаються відкритими; до явного logout cookie може ще відновити provider identity, хоча SQL tombstone блокує дані.
- **D3, частково:** додано доступні учаснику `match_cases` і `match_case_approvals`, перевірки participant/case/party, захист від зміни локальної сесії під час експорту. Експорт і UI явно кажуть `partial`; JSON містить список пропущених категорій та operator follow-up. Для недоступних через поточні RPC/гранти таблиць права не розширювалися.
- **C1:** обидва SW відхиляють усі query URLs; CACHE names не змінено. Offline працює для канонічних публічних URLs. Private/query LAB URL offline завершується мережевою відмовою; окрема канонічна сторінка відкривається без приватної кімнати/удаваного live AI. Старі позитивні query-cache очікування замінено перевіркою нового контракту; негативні перевірки збережено/посилено.
- **C2:** тимчасовий `synera.adaptive.session-check` тепер є в інвентарі sessionStorage privacy centre. Runtime-проба, як і раніше, негайно видаляє ключ.
