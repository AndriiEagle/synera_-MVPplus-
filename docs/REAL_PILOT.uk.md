# Synera: реальні профілі, AI за запитом, одна домовленість

NOW — завершення пілоту PWA для реальних людей. APK/IPA, магазини, платежі, боти та платні фонові завдання виключені з поточного запуску.

A RECOMMENDED — PWA + наявний Supabase; AI допомагає один раз структурувати власний опис, а пошук порівнює підтверджені умови без API-виклику на кожну картку.
B FALLBACK — ті самі поля заповнюються вручну або через власний ChatGPT з імпортом короткої JSON-відповіді. Умови й приватність не змінюються.

## AI: що працює, а що ще не підтверджено

Редактор приймає перевірену JSON-відповідь з власного ChatGPT, показує цитати, дозволяє обрати навички й лише потім переносить їх у форму. Цей шлях перевірений тестовою відповіддю та фактичною відповіддю локальної моделі; реальний ChatGPT-запит від імені користувача не виконувався.

Вбудований локальний endpoint підключений до наявного DOMOVYK. Перша спроба зупинилася на cpu_or_ram_pressure. Після дозволу ресурcного gate одна генерація не пройшла інтеграційну перевірку. Додано строгу JSON-схему через наявний canonical adapter; наступний запит повернув HTTP 200. Модель визначила design/sales з точними цитатами й трьома уточненнями. Фактичну відповідь перевірено та перенесено у приватну тестову форму. Це n=1 для успішного сценарію, а не доказ якості на довільних реальних профілях.

Дві фактичні локальні генерації: gemma-4-e2b-day.gguf, 559 вхідних + 330 вихідних = 889 токенів, зовнішніх викликів 0, USD 0.00. Канонічні receipts зіставлено з хешами; відхилений результат збережений у статусі rejected, успішний — з вимогою людського перегляду. Захист ресурсів і приватності не обходився.

Автоматичний AI для публічного сайту ще не розгорнутий. Локальний endpoint не можна відкрити на телефоні Гілберта через опубліковану сторінку. Для цього потрібен окремо погоджений хост/провайдер, спосіб захисту даних, точний ліміт витрат, серверна автентифікація, квоти та реальна перевірка результату. Поточний код не вмикає платний fallback і не містить ключів провайдера.

Прототип навмисно працює з 7 професійними категоріями. Це не семантичний пошук по необмежених резюме й не AGI або незалежний арбітраж. Висновки не є рішеннями щодо людей чи підписаними угодами.

## Що блокує повний запуск

| Перевірка | Поточний стан |
| --- | --- |
| Supabase Auth | HTTP 402; повторна перевірка 2026-09-05 16:27 UTC |
| Нові таблиці/RLS | real-pilot.proposal.sql готовий до перегляду, не застосований |
| SQL acceptance | real-pilot.acceptance.sql підготовлений, не запущений; локального Postgres/CLI немає |
| Листи реєстрації | Власний SMTP не налаштований для зовнішніх учасників |
| HTTPS | Пакет локальний, не опублікований |
| Автоматичний публічний AI | Не розгорнутий; кошти не погоджені |
| Два реальні акаунти | Реєстрація, повідомлення та збереження між пристроями ще не перевірені |
| Android/iPhone | Мобільна ширина в браузері перевірена; встановлення на фізичних телефонах не перевірене |

Стандартна пошта Supabase обмежена адресами команди проєкту та наразі двома листами на годину; Гілберту потрібен налаштований SMTP, а не адміністративний доступ до організації. [Офіційна документація](https://supabase.com/docs/guides/auth/auth-smtp).

PWA встановлюється через браузер після HTTPS-публікації; localhost цього ПК не є посиланням для телефона. [Вимоги PWA](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/Making_PWAs_installable).

## Один порядок запуску

Готовий Support-запит → відновлений Auth → застосування й перевірка RLS → SMTP/поштові шаблони → HTTPS → два реальні акаунти → Android та iPhone.

1. Оператор погоджує відправлення docs/SUPABASE_SUPPORT_REQUEST.md. Звернення просить відновити Free-проєкт без апгрейду чи видалення.
2. Після відновлення — зберегти вимкненою серверну реєстрацію, створити міграцію з нової SQL-пропозиції й застосувати лише до виділеного проєкту.
3. Виконати транзакційний SQL acceptance; перевірити відсутність залишених фікстур, security/performance advisors і прямі неавторизовані запити.
4. Налаштувати пошту, шаблони token_hash для підтвердження/відновлення та точний HTTPS redirect allowlist; перевірити доставку на дозволену зовнішню адресу.
5. Опублікувати лише web_launch/dist-real; залишити registrationEnabled=false до завершення серверних перевірок. Перевірити, що домен не роздає SQL, тести чи конфігурацію секретів.
6. Два добровільні учасники створюють власні акаунти, підтверджують правила, імпортують свої профілі, перевіряють взаємну користь, запрошення, повідомлення, блокування та експорт. Без підписання договорів від їхнього імені.
7. Встановити PWA на домашні екрани Android/Chrome й iPhone/Safari. Підтвердити повторний вхід, повернення з листа, вихід і відсутність сторонніх даних в офлайн-кеші.

PARKED — монетизація, платний фоновий AI, широке збирання/скрейпінг профілів, push, магазини, APK/IPA та гарантії вірусності.
