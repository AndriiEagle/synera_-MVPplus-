# Нейтральний локальний помічник Synera

Лінія ADAPT, база `f69882f1e5e5b5085449505db0487351fc19c90b`, гілка `claude/synera-adapt-20261030`.
Це детерміновані локальні правила. Тут немає підключення до моделі, мережевих запитів або автономних рішень за людей.
«Суверенний» у цій реалізації означає незалежне від зовнішнього AI виконання цих правил на пристрої. Це не заява про країну хостингу чи юридичну сертифікацію.

## Контракт

```js
import { suggest, suggestAll } from '../web_launch/sovereign.mjs';
const context = {
  lang: 'uk', // uk | de | en
  collaborationId: 'local-project-1',
  now: 1793318400000, // ін'єкція годинника, жодних прихованих таймерів
  parties: [
    { id:'a', give:['design'], need:['sales'], goal:'MVP', limits:['1 hour'], formats:['remote'] },
    { id:'b', give:['sales'], need:['design'], goal:'MVP', limits:['1 hour'], formats:['remote'] },
  ],
  events: [],
  dismissed: [],
};
suggest(context); // { text, why, kind, confidence:'rule' } | null
suggestAll(context); // [{ id, text, why, kind, confidence:'rule' }, ...]
```

`confidence:'rule'` позначає походження, а не ймовірність чи оцінку людини. Некоректний набір учасників або менше двох дає `null`/порожній список. Функції не змінюють входи. Масив учасників канонічно впорядковується; `viewerId` не впливає на підказки. Мова змінює лише формулювання. Для повідомлень потрібні `id`, `actor`, `collaborationId`; сторонні автори, адресати й інші співпраці відкидаються. Порядок масиву подій — порядок журналу.

### Правила

| kind | Умова й пояснення |
|---|---|
| `common` | Точний збіг нормалізованого тегу `give` однієї сторони з `need` іншої. Ребра проходять наявний `solveBMatching` з квотою до всіх інших учасників. `why` містить напрямок, тег, заявлені цілі, межі та формати кожного. Явно несумісні формати відсікаються. |
| `next` | Однакове для кожного запитання про внесок, прохання, час і межу. Жодної лестощі чи припущення згоди. |
| `clarity` | Для останнього повідомлення показуються невказані/нерозпізнані слоти ask/offer/time/limit. Явна структура `concrete:{ask,offer,time,limit}` має пріоритет. Інакше використовуються короткі відкриті мовні шаблони uk/de/en. |
| `triangle` | Для трьох учасників — однакове право назвати внесок, потребу й межу; `why` перелічує всі три сторони. |

Мовні шаблони ясності обмежені. Наприклад, «Can you send the sketch? I offer sales tomorrow 10:00, max 1 hour» розпізнає чотири слоти. Незвична фраза може отримати зайве уточнення; це не вердикт про автора. Довільні текстові межі показуються для спільного погодження, а не оголошуються автоматично виконаними. Різні цілі самі по собі не доводять несумісності.

## Рівна взаємність

`analyzeBalance(context)` у `web_launch/balance.mjs` повертає окремі сигнали `{kind,text,why,counts,evidence}`. Загального балу, діагнозу, оцінки довіри чи психологічного профілю немає. Правила симетричні для двох, трьох і більше учасників.

| kind | Дані та запобіжник |
|---|---|
| `contributions` | Різна кількість подій `contribution` з `concrete:true`, `delivered:true`, непорожнім `contributionId`. Повтор внеску одного автора не подвоює рахунок. `giveTake` показує передано/отримано та їхнє відношення; при нулі отриманих — `null`, без нескінченності чи морального висновку. Для групового внеску без адресата отримувачі не вигадуються. |
| `asks` | Щонайменше два `ask` з явним `hasOffer:false`, нерівномірно між сторонами. Невідоме не дорівнює «не запропонував». |
| `pressure` | В односторонніх `message` є прозорі вирази терміновості/тиску uk/de/en. Потрібна перевірка контексту; цитування та іронію правило не розуміє. |
| `after_delivery` | `deadline_moved` або `cancel` після конкретного внеску іншого учасника в тій самій `agreementId`. Без попереднього внеску сигналу немає. |
| `terms` | Щонайменше дві нерівномірні `terms_changed` з явним `agreed:false`. Спільно погоджені зміни не рахуються. |
| `delayed` | `confirmed` з revision/часом понад добу тому, а не всі учасники підтвердили ту саму версію. Затримка не означає відмову або провину. |

Порожня нова співпраця не дає жодного сигналу. Події мають стабільні унікальні ID. Підтвердження внеску тут — локальна нотатка, не автентифікована згода отримувача. Різні внески можуть мати різну цінність: співвідношення кількості не визначає справедливу оплату чи користь. Цей контраргумент прямо показаний в огляді.

`sovereign-ui.mjs` рендерить через `textContent`, показує «Чому», дозволяє приховати кожну підказку/сигнал. Приховування зберігається в пам'яті для цієї співпраці під час оновлення розмови. «Пауза» виконує лише явну локальну дію; автоматичного блокування немає. «Повідомити оператору» відкриває пояснення й наявний контакт у правилах. Нічого не надсилається та не додається до звернення автоматично.

## Інтеграція

- Симуляція: окремий явно вигаданий сценарій Mira/Leo · Demo показує сторону, яка отримала внесок, просить далі й поки не віддала свого. Це сценарна роль, не характеристика людини. У власній Demo-розмові є нейтральні наступні кроки й уточнення.
- Triangle: одна панель для спільного екрана, усі три сторони в поясненні. Явно позначені завершеними локальні кроки живлять лічильник внесків; сама обіцянка/текст внеску не вважається доставкою. Поточні бюджетні «так» враховуються як локальні нотатки підтвердження. Пауза зупиняє добровільну чергу, якщо вона є.
- Жодна панель не публікується в профіль, не передається третім особам і не надсилається іншому пристрою. Однаковий локальний огляд перевірений; синхронна доставка двом реальним авторизованим людям потребує окремої серверної лінії й приймання.

Майбутній модельний адаптер має зберегти `suggest(context) -> {text,why,kind,confidence}|null`, явну згоду на конкретне передавання, мінімізацію матеріалу, однаковий результат для всіх сторін, можливість відмови та ті самі незалежні перевірки симетрії/меж. Ця лінія не дозволяє й не запускає live-AI.
