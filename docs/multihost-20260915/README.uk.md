## Рішення про GitHub-базу

Публічна `main` перевірена на `ba4e07567dc06139c336f9ad9262af88f31c5e7d`; це старий Flutter/Firebase checkout. Сучасне локальне джерело `2aa7fae6a4f002ed880cb97ec780de41e328af97` містить web_launch/Neon. Різниця: 12 комітів, 116 файлів, 10698 доданих і 13 видалених рядків. Цей PR додає лише цей каталог документації та локальні перевірки специфікації. Він не робить сучасне джерело доступним на другому хості.

**Передумова SOURCE_PUBLICATION_REVIEW:** інтегратор має перевірити склад сучасного source snapshot, ліцензії, секрети, персональні дані, generated artifacts і залежності; вибрати мінімальний чистий набір у наступному source PR; перевірити offline build, тести та зіставлення хешів. Не переносити всю локальну історію автоматично. Після перенесення зв’язати новий публічний commit із локальними source hashes і повторно перевірити залежні acceptance fixtures. До цього V6 implementation на публічній базі заблокована.

GitHub повернув `Branch not protected` для `main`; список repository rulesets був порожній. Налаштування захисту не змінювалися. До появи перевірених правил застосовується ручний review: окремий reviewer, один інтегратор, жодного merge лише тому, що push успішний.

## Межі доказів

- Soul V6 і workflow перевірені за локальними файлами; оригінали V5/V6 залишаються незміненими. Публічний V6_TASKS — очищена проєкція, а не byte-identical копія. Original hashes наведені в manifest. Старі особисті шляхи й task-scoped платний cap не перенесені.
- У доступній Synera handoff-папці KI-BUS був лише Soul snapshot. **TERRA_LATEST_UNRECONCILED**: немає підтвердження найновішої спільної версії.
- Історичні 140/140 тестів не замінюють поточне product acceptance. Відтворено лише client transport defect: A може передати approval B. Live DB exploit не доведений; виправлення не виконане.
- Leases/fencing/global admission нижче — необхідний контракт. Його розподілене виконання на 2–3 хостах не підтверджене. До доказу — один активний execution host, інші можуть читати/рев’ювати.
- Пілот 10 унікальних пар / 14 днів / 5 узгоджених briefs / 3 прийнятих trial outcomes — гіпотеза learning gate. Це не виміряна виручка й не PMF.

## Локальна перевірка пакета

З кореня цього репозиторію, з наявним Python 3:

```text
python -B docs/multihost-20260915/check_package.py --final
python -B -m unittest discover -s docs/multihost-20260915 -p "test_*.py"
git diff --check
```

Ці команди не потребують сучасного source checkout, мережі чи моделей. Вони перевіряють документаційні контракти й synthetic examples; не доводять роботу runtime, бази, UI, бюджету провайдера або майбутнього агента. `ACCEPTANCE.json` створена після byte-for-byte readback усіх 15 файлів першого GitHub payload commit. Фінальний evidence commit додає цю квитанцію; його remote HEAD і blob readback фіксуються в PR та вихідній задачі. `--final` відхиляє відсутню квитанцію, незавершені шари або змінені хеші; без прапорця доступна перевірка чернетки.
