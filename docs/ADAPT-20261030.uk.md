## A1 — лише пристрій і явне «Так»

`web_launch/adapt-observer.mjs` є єдиним новим власником спостережень. Ключ — **`synera.adapt.v1`** у localStorage. За замовчуванням спостереження вимкнені. Добровільний перемикач і пояснення стоять у наявному меню «Мова і вигляд», окремого налаштування перед корисною дією немає.

| Поле | Що зберігає |
|---|---|
| `enabled`, `sessions`, `lastActivity`, `sessionStart`, `acted`, `offeredSession` | Згода, межа сесії після 30 хв бездіяльності й захист від повтору. Перезавантаження саме по собі не є новою сесією. |
| `signals.sections` | Лічильники лише home/simulation/studio/triangle/rooms/journal/profile; без маршрутів, ID людей і назв приватних кімнат. |
| `signals.input` | Кількість voice/text; без тексту й аудіо. Звичайне введення зведене за подіями, а не за кожною клавішею. |
| `signals.hours` | Чотири 6-годинні частини доби; без історії точних годин кожної дії. |
| `signals.zoom` | normal/large (від 1.25), без відбитка пристрою. |
| `signals.firstAction` | До 10 с / 10–20 с / від 20 с до першої дії в поточній сесії. |
| `signals.fieldLanguage` | Лічильники uk/de/en для offers/seeks/goal/limits. Явна мова поля або вибрана мова інтерфейсу, без вгадування мови з тексту. |
| `manual`, `choices`, `pending`, `applied`, `declined` | Ручний пріоритет, одна пропозиція, список прийнятого з попереднім значенням і відмови. |

Тільки на кожній третій справжній сесії можна запропонувати щонайбільше одну зміну. Поки людина пише, відкрито діалог/тур або навчальну підказку, нова пропозиція не показується. Доступні два обережні правила:

- Мікрофон першим: щонайменше три голосові сигнали, їх більше ніж удвічі від текстових; потрібен реальний позначений голосовий контрол. Без нього ця пропозиція не з'являється.
- Більші кнопки/відступи: щонайменше три сигнали збільшеного масштабу й поточний вигляд ще не large.

«Так / Ні / Більше не питати» не змінюють робочий екран до прийняття. Відхилений вид зміни не пропонується знову до скидання. «Більше не питати» вимикає збір і стирає його лічильники. Прийняте видно в «Що Synera підлаштувала»; кожну зміну можна скасувати. Скидання адаптації стирає спостереження й скасовує прийняте, зберігаючи явні ручні рішення. Загальне наявне скидання персоналізації залишається окремою ширшою дією.

Ручний вибір щільності ніколи не замінюється пропозицією. Наявні збережені зміни вигляду трактуються консервативно як ручні. Після перезапуску попереднє значення для скасування береться зі збереженого списку, а не вгадується. Відкликання згоди/стирання в іншій вкладці перечитується перед наступним записом. При недоступному сховищі спостереження вимкнені, ручні контролі працюють у пам'яті. Reduced motion не запускає анімацій.

Старий чистий API `adaptive.mjs` збережений для сумісності та наявних тестів. Його UI-збір вимкнено, старі ручні палітри/щільності/підказки залишилися. Нові спостереження не дублюються в `synera.adaptive.preferences.v1` чи sessionStorage.

### Шов для голосової лінії

```js
// Лише завершена взаємодія, без тексту/аудіо:
document.dispatchEvent(new CustomEvent('synera:input-mode', {detail:{mode:'voice'}}));
document.dispatchEvent(new CustomEvent('synera:field-language', {detail:{field:'offers',lang:'de'}}));
// Явне ручне рішення має пріоритет назавжди до ширшого скидання:
document.dispatchEvent(new CustomEvent('synera:voice-preference', {detail:{first:false}}));
```

Голосовий контрол позначається `[data-voice-input]`, розміщується в flex/grid-групі. Клас `adapt-voice-first` використовує `order:-1`. Власник голосової лінії має подавати подію тільки після фактичного використання, не після самого кліку дозволу мікрофона. Нативний `insertFromDictation`, якщо браузер його надає, враховується окремо. Модуль не відкриває мікрофон і не створює speech/network-сервісу. Живий голосовий шлях перевіряється після злиття з VOICE; тут він перевірений лише сигналами й контрактом.

## A4 — схожі на корисних партнерів

`journal-matching.mjs` отримує тільки явно переданий власний локальний журнал. Нічого не шукає в мережі й не створює другого сховища. У симуляції людина добровільно вибирає професійний тег внеску/потреби, окремо дозволяє використання журналу й після результату сама позначає його корисним.

Використовуються лише `result` з `source:'visitor'`, власним `ownerId`, `useful:true`, `matchingConsent:true` та збереженим структурованим `partner`. Вихід пояснює спільні заявлені теги з партнером попереднього корисного результату. Кандидат має відповідати поточним give/need в обох напрямках; явно несумісні формати відсікаються. Це додатковий критерій релевантності, а не доказ майбутнього успіху. Імена й тексти не беруть участі в обчисленні; теги не виводяться з вибраного партнера чи приватного повідомлення.

Використано наявний `synera.journal.v1`: записи `matching_profile`, `matching_consent`, добровільний корисний `result`. Його чинний 30-денний строк не подовжується від читання. Відкликання ховає добір; повне стирання журналу очищує джерела. Спільний браузер не встановлює особу: тут локальний власний вибір, а не серверна авторизація.
