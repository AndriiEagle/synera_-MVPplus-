## S2 — що реально працює

1. Свіжі `dist-real` і `dist-neon-ci` проходять CI pattern scan. Ін’єкції private key,
   DB URL, provider key і secret binding відхиляються, навіть у nested extensionless
   файлі; output не друкує знайдений секрет. Pattern scan не гарантує виявлення всіх
   можливих секретів, зокрема обфускованих.
2. Additive RLS proposal зберігає owner-executed RPC через точну owner maintenance
   policy. Role ownership/membership/BYPASSRLS — частина assertion. Це не захист від
   адміністратора. Реальні PostgreSQL checks із **non-superuser, non-BYPASS owner**
   підтвердили own-profile write, cross-account denial, documentary events і complete
   application erasure. Source migrations історичних релізів не змінені.
3. `generateKit` завершується `writeKitArtifacts`: readiness читається **перед першим
   записом ZIP/manifest**. `--audience open-registration` відхиляється, поки DPA,
   published notice з реквізитами, live deletion, DPIA decision і transfer basis не true.
   Empty/missing/partial/string/null/false теж блокуються; попередній kit не перезаписується.
   Default `closed-pilot` проходить цю браму, зберігаючи всі свої чинні gates та
   `SYNERA_OPEN_REGISTRATION=false`. Навіть green readiness не перемикає live flag.
4. Новий local Demo submit записує текст **видимих перед дією** повідомлень і SHA,
   версію, locale, purpose, recipient, expires_at та action. Legacy entries не мігрують
   у фальшиву згоду. Reload/export/erase й cross-tab правила збережені; відкладений
   digest не воскресить стертий журнал. Withdraw є явною подією API контракту журналу,
   не новим серверним UI чи cloud consent. SQL proposal перевіряє text/hash і забороняє
   client UPDATE/DELETE; complete erasure каскадно прибирає нові записи через pilot consent.
5. [Erasure ledger](secure-20261030/ERASURE-LEDGER.uk.md) — лише design + in-memory double:
   HMAC із окремим ключем, idempotent pending intent і блокування restore. Реального
   незалежного сховища/PITR-drill/Neon Auth deletion немає.
6. Worker invocation logging note й доповнений 72-hour runbook знаходяться в kit generator
   та [privacy design](PRIVACY-BY-DESIGN-20261029.uk.md). Реальні platform settings не змінені.

коректність live Neon role graph, усіх privileged RPC, JWT, backup чи договорів.

keys, незалежного erasure ledger, signed live JWT/two accounts, DPA/DPIA/transfer basis
не замасковані новими PASS. Open readiness навмисно лишається false.

Claude; жодного owner approval/stabilizer export не підписано від імені оператора.
