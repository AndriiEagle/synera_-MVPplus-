## Як застосунок потрапить на телефон

**A RECOMMENDED — PWA.** Одна опублікована HTTPS-адреса для обох телефонів, іконка на домашньому екрані, окреме вікно застосунку. Перший запуск потребує інтернету; після завантаження офлайн доступне демо. Встановлення PWA не вимагає APK або публікації в магазині. [MDN](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/Making_PWAs_installable).

**B FALLBACK — native Flutter.** Окремий проєкт відновлення старого Flutter-клієнта: встановити SDK після дозволу, перенести Firebase-залежні екрани на Supabase, перевірити Android release signing та пристрій. Для iPhone потрібні засоби Apple для збірки/підпису й маршрут TestFlight/App Store. APK не встановлюється на iPhone. [TestFlight](https://developer.apple.com/testflight/).

На цьому Windows-хості зараз знайдено Node, але не flutter, dart, adb, java, supabase чи psql у PATH. Docker CLI є, daemon недоступний. Тому APK/IPA й локальне виконання нового SQL не перевірялися. Встановлення інструментів не виконувалось.

## Порядок до справжнього користування

1. **Відновити API Supabase.** Повторна read-only перевірка 2026-09-05: `/auth/v1/settings` → HTTP 402. Management API показує `ACTIVE_HEALTHY`, SQL доступний: 0 акаунтів, 0 профілів, 0 зустрічей, база 10 816 659 байтів. Це різні рівні доступності; стан бази не доводить доступність Auth. Залишити `registrationEnabled:false`. Не створювати акаунти для обходу квоти. Причину історичного обмеження та момент зняття має підтвердити Support. [Квоти](https://supabase.com/docs/guides/platform/database-size).
2. **Публікувати перевірений пакет на HTTPS.** Для демо — тільки `web_launch/dist-demo`; для реального пілоту після всіх перевірок — `dist`. Cloudflare Pages Direct Upload приймає готову папку/ZIP. Погодити конкретний акаунт, назву `synera-pilot` (або доступну заміну), безплатний тариф і публічність. В історії репозиторію є старі секрети/браузерні файли: завантажувати тільки allowlist-пакет. [Direct Upload](https://developers.cloudflare.com/pages/get-started/direct-upload/).
3. **Налаштувати доставку листів.** Supabase default SMTP надсилає лише адресам команди проєкту й має низький ліміт. Gilbert не повинен отримувати адміндоступ для отримання листа. Підключити погоджений SMTP і перевіреного відправника; тримати підтвердження email увімкненим. Не використовувати публічний контактний Gmail як SMTP-секрет. [Supabase SMTP](https://supabase.com/docs/guides/auth/auth-smtp).
4. **Підготувати серверне підтвердження правил.** `supabase/pilot-consent.proposal.sql` — лише кандидат, не застосована міграція. Виконати його в локальній/окремо погодженій тестовій БД, перевірити RLS і згенерувати міграцію CLI. Тести: без згоди доступ закритий; A не може читати/писати згоду B; timestamp задає сервер; metadata Auth не дає прав; видалення акаунта прибирає згоду. Після дозволу застосувати тільки до `synera-demo`, перевірити advisors, тоді ввімкнути `pilotSafetyEnabled`.
5. **Закрити роботу з даними й зверненнями.** Оператор і контакт уже в `legal.html`: Andrii Pokrovskyi, andriipokrovskyi@gmail.com (надано власником для публікації). Перед реальними даними перевірити умови Supabase/хостингу, повідомлення про передачу в Німеччину, строки backup retention, виконання видалення/скарги. Наразі видалення акаунта й модерація — ручний маршрут через оператора; автоматичні block/report/delete ще не реалізовані. Підтвердження правил не замінює договір про співпрацю чи кваліфікований підпис. [FDPIC](https://www.edoeb.admin.ch/en/duty-to-provide-information).
6. **Пройти реальний тест двох акаунтів.** Andrii і другий погоджений тестер: signup → email confirmation → новий вхід → серверна згода → імпорт → приватний профіль → увімкнення видимості → пошук → запит → прийняття → перезапуск → збережений результат. Третій акаунт і anon не читають запрошення. Окремо перевірити відновлення пароля, вихід, refresh та повторний імпорт. Лише після цього відкрити реєстрацію.
7. **Встановити на Android.** Відкрити HTTPS-адресу в Chrome → «Встановити Synera» або меню → «Встановити застосунок / Додати на головний екран» → запустити іконку. Перевірити повторний вхід після закриття і налаштування запам’ятовування на особистому пристрої. APK на цьому етапі не потрібен.
8. **Передати Gilbert.** Сам користувач поширює той самий HTTPS-лінк. Android — крок вище. iPhone — Safari → Поділитися → На початковий екран → Відкривати як вебпрограму (якщо доступно) → Додати. Перевірити на реальному iPhone; браузерний viewport не замінює пристрій. Автоматичне надсилання Gilbert не виконувалось.

## Email callbacks, які очікує код

Після вибору хостингу `publicSiteUrl` має містити лише його HTTPS origin. Supabase Site URL і дозволений redirect — та сама адреса без широких wildcard.

У шаблоні **Confirm signup** використати посилання `{{ .SiteURL }}/?token_hash={{ .TokenHash }}&type=email`.
У **Reset password**: `{{ .SiteURL }}/?token_hash={{ .TokenHash }}&type=recovery`.
Код прибирає параметри з адреси перед зверненням до Auth, перевіряє token hash на сервері, а пароль змінює лише після введення користувачем. Стандартний callback із fragment-токенами не підключений: не відкривати реєстрацію зі старим шаблоном. Вміст ключів і паролів не логувати.

## Перенесення власних даних

- LinkedIn: офіційний export → свій `Profile.csv` → прапорець права перенесення → файл → прев’ю → «Шукаю» → зберегти. Підтримано один рядок профілю, а не Connections.csv чи весь ZIP. [LinkedIn export](https://www.linkedin.com/help/linkedin/answer/a1339364/downloading-your-account-data).
- LinkedIn OIDC дає базовий профіль/вхід, не весь CV, зв’язки чи приватне листування. Для цього потрібна окрема зареєстрована інтеграція; згода людини сама по собі не розширює API-права. [Офіційна OIDC-документація](https://learn.microsoft.com/en-us/linkedin/consumer/integrations/self-serve/sign-in-with-linkedin-v2).
- GPT: у вікні імпорту скопіювати короткий промпт → виконати у власному чаті → перенести лише JSON профілю → перевірити. Synera не входить у ChatGPT і не читає історію автоматично. Повний export ChatGPT містить більше даних, ніж потрібно для цього сценарію. [OpenAI export](https://help.openai.com/en/articles/7260999-how-do-i-export-my-chatgpt-history-and-data).

## Локально перевірено

- 45 Node-тестів: базові 33 + 12 нових, включно з CSV, GPT JSON, згодами, сесією, PWA boundaries, 10 ботами й кандидатом API-пакета.
- Browser smoke: 10 профілів; запит Leo очікує → наступна година → прийнято з позначкою симуляції; карта показує 10 точок, тайли OpenStreetMap завантажилися після явного ввімкнення.
- Viewport 390×844 (375 CSS px для документа через scrollbar): горизонтального переповнення немає. Це перевірка адаптивності, не фізичний Android/iPhone.
- Static build: 25 файлів; публікація не виконана. PWA manifest/PNG/allowlist/SW правила перевірені локально. Реальне встановлення на телефон і повний офлайн-запуск ще потребують device smoke.
- Платних викликів 0. Новий SQL-кандидат і жива реєстрація не перевірені виконанням.

**Межа готовності:** можливість натиснути «Спробувати демо» не означає, що зареєстрований користувач чи дані збережені в Supabase.
