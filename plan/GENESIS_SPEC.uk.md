## §1 Executive DNA (одна сторінка)

1. **Атом продукту** — не «знайомство», а пара, доведена до підтвердженого малого бізнес-кейсу: потреба → взаємна користь → дві згоди → пробний обсяг/умови → результат → відкладений двобічний відгук.
2. **Розум у схемі, не в моделі.** Runtime = 2 дешеві виклики на пару максимум (структурування бріфу, чернетка пояснення), все інше детермінізм: matcher, terms guard, інвалідація, funnel. Модель, що не може вигадати ціну, — розумніший продукт.
3. **Чесність як архітектура.** binding:false назавжди; PRESENT_BUT_UNTESTED не знімається тестами; знаменник воронки ніколи не чиститься (ghosts і missing feedback запроектовані).
4. **Ядро готове — воно не підключене.** 97/97 тестів; вся робота v4 = з'єднання (хвилі A/B/G) + нові шари (legal, import, telemetry) + рішення оператора.
5. **Свобода користувача = сила і телеметрія.** 7 гранулярних згод, export/delete завжди видимі; чим більший контроль, тим чистіші дані для оператора.

## §2 Геометрія системи

- **Пари** = невпорядковані 2-підмножини учасників; повторні кейси тієї ж пари звітуються окремо (lessons: MODEL_REVIEW §9).
- **Решітка згод** = 2^7 станів сімки дозволів; reject-стан будь-якого виміру проєктується на стінки (comparison=0 ⇒ жодного output). Симетрія: інваріант відносно перестановки сторін (role-swap тести).
- **Режими × дозволи** = 5 режимів (4 активні + joint_project паркований) × 7 дозволів — матриця, у якій жодна клітинка не заливається іншою (P01–P16 як трасування).
- **DAG** = направлена решітка: `depends_on` — авторитет, маркери — вузли; хвилі фрактальні: кожна реплікує схему кроку (anchor → change → marker → test → rollback), від A до I.
- **Версійність** = ланцюг хешів: brief v1/v2 → matcher output version → case material SHA-256 → SQL generation byte-proof. Зміна матеріального → стрибок версії + обнулення approvals (математично: guard = перевірка рівності хеша в момент авторизації).
