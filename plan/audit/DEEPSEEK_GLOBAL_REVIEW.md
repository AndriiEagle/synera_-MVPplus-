## (a) Телеметрія «максимум легально» — вердикт: ФУНДАМЕНТ СИЛЬНИЙ, ЗБІР ЩЕ НЕ ПУЩЕНИЙ

- Легальність зашита в БД, не в обіцянках: restrictive RLS-політика `cases_consent` вимагає запису в `pilot_consents` з версією політики (`case-state.migration.sql:157-159`) — обійти згодою UI неможливо.
- Публікація статистики через k=5 + DP-шум (`k-anon.mjs:5,12`), WTP відкидає відповідь без згоди (`wtp.mjs:15 CONSENT_REQUIRED`).
- Але event-канал збору не пущений (`neon/worker.mjs` — без телеметрії) — свідомо, до Q3 + дерева метрик. Деталі: `plan/audit/TELEMETRY_LEGALITY_AUDIT.md`.

## (b) Автоперсоналізація: людський confirm — ТАК, і це головна мудрість системи

- Cascade: `L1-L3: ['select','forge','preview','confirm','deploy','log']` — **confirm обовʼязковий етап** перед deploy (`cascade_orchestrator.mjs:17-19`).
- «Тихих змін немає»: `confirm(planId, operatorId)` кидає «Потрібне підтвердження оператора» при порожньому operatorId (`cascade_orchestrator.mjs:131-133`).
- Rollback і log immutable hash-chained — деплой завжди зворотний і з аудитом.
- Флаги OFF за замовчуванням для грошей/живої бази/деплою — вся машина 8 у цьому режимі (qr_bill OFF, migration dry-run default, vector store локальний).

- Оригінал `style.css` = 1816 рядків сырого CSS (200 класів-селекторів); launch = 162 семантичні custom properties + 146 compat-токенів у `tokens.css` (385 рядків; cycle 4 довів: до 2026-09-23 семантичний шар НЕ був підключений до рендеру — 146 висячих var() → виправлено, див. `DESIGN_MAP_AUDIT.md` Cycle 4) + каталог компонентів зі станами + WCAG-гейт у token_forge (12t) + prefers-reduced-motion (фаза 1).
- Деталі з числами: `plan/audit/DESIGN_MAP_AUDIT.md` (картка H).
- Відкритий гап: C06.L1 brand sheet (голос/заборони письмово) — без нього «впізнаваність» не фіксована документом.

## (d) Глобальна карта: чесна легальна база, гапи — продуктові

- Наявне: tile-абстракція, маркер-токени з tokens.css, GEO-01 guard, opt-in OSM тумблер, GPS не запитується, попередження про IP прямо в UI (`index.html:25`).
- Бракує до «трошки краще за оригінал»: кластеризація маркерів, event heat-оверлеї, dark tiles у бренд-палітрі, маршрути «пари → місце зустрічі». Це UI-робота після C08/бренд-листа, не блокер.

## Темні сторони і залежності — система спроєктована ПРОТИ exploitation

1. Людину не оцінює балом (інваріант §3.1) — немає «рейтингу людей», немає свайп-казино петлі.
2. Згода окрема від участі і ревокабельна; матеріальна зміна стирає погодження (proof-state FSM).
3. Монетизація не продає довіру: `matching_is_free`, `trust_never_sold` гейти (tier-matrix); bілінг flag OFF.
4. Вірусність з k-гейтом — зростання не карає приватність (k-anon + consent).
5. Автоперсоналізація ніколи не тягне руку без оператора (confirm-гейт + MA4 «без holdout win + human approval не промотується»).

## Вердикт глобальної когерентності: **COHERENT** — екосистема зшита в один контур

Айсберг внизу (RLS/consent/k-anon/audit/rollback) тримає верхівку (Deep Matching) і персоналізацію (cascade з людським confirm) на одному легальному фундаменті. Топ-5 найдорожчих гапів для «110%»:
1. Q3 live-міграція (все готово, один перемикач).
2. Юрист 30 хв (пакет готовий).
3. Фаза-9: серверний event-pipeline ЗА деревом метрик (C09.L4) — не до, а після.
4. C08 адаптивний дизайн-агент (0% — ціла фаза).
5. Brand sheet + серверний field enforcement (точкові).

Ризики чесно: система свідомо НЕ монетизує увагу і не створює залежності (відсутність infinite-scroll-механік у matching, consent-gates) — це бізнес-мудрість, не недоробка.
