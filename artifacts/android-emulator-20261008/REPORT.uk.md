# Android: перенесення прийняте, UI-перевірка заблокована

Дата: 2026-10-08. Checkout: synera-premium-pwa-variant, codex/synera-product-20261002.

## Прийнято

- Згенерований RAM-кеш 2 684 420 096 байтів перенесено з C на D:/Moved/SyneraAndroidCache-20261008/ram.img. Два послідовні порівняння SHA-256 і розміру збіглися; видалено лише перевірений оригінал C. Receipt: RAM_OFFLOAD.json. Бази, SDK та користувацькі файли не видалялися.
- `-no-snapstorage -feature -QuickbootFileBacked` додано до локального запуску за документацією встановленого emulator.exe і advancedFeatures.ini. Наступний запуск не створив ram.img; після зупинки його також немає. Резерв місця збережений: 10 GiB перед стартом, 8 GiB під час очікування boot.
- Android 16 завантажився, 1080x2400; це лише boot, не приймання інтерфейсу. Доказ: C_BOOT.json.
- Виправлено діагностичний дефект: uiautomator іноді повертає exit 0 разом з ERROR і залишає старий XML. Тепер кожен dump має унікальний шлях і вимагає підтвердження успішного запису перед читанням.
- Семантичний regression gate: до виправлення 1 FAIL / 1 PASS; після 2 PASS. Негативний випадок exit 0 + ERROR + доступний старий XML доводить, що читання старого документа заблоковане. Успішний випадок читає саме новий шлях. Дві перевірки фактичного diff: збережено межу serial emulator-5580, резерв C, користувацькі дані та сторонню dirty-правку journey-ui.mjs.

## Не прийнято / блокери

- settled-home.png і свіжий settled-home.xml показують **System UI isn't responding**. Ранній recovered-home.xml не прийнятий: створений старим помилковим діагностичним шляхом. PNG залишається окремим знімком.
- Android мав перезапуск системних процесів / DeadSystemException. CPU sample показав load близько 24 і 19% iowait. Це спостереження, не доведена першопричина. Вільна RAM Windows під час роботи була близько 3,5 GiB.
- Повторний автоматичний запуск Chrome через ADB після прямого дозволу користувача відхилено політикою інструмента. Відмова не пояснила точнішу причину. Обходу та повторної спроби іншим транспортом не було.
- Після зупинки планувався один видимий запуск з GPU host. Він **не почався**: перевірка C виявила менше 10 GiB. Наприкінці приблизно 4,7 GiB вільно; Windows pagefile має 13 794 MiB allocation. Без попереднього заміру не доведено, що саме він спричинив усе зменшення. C_FINAL.json містить фактичні числа. Глобальні параметри Windows не змінені.
- Емулятор і наш локальний HTTP-сервер зупинені. Raw runtime/logcat залишено локально, не додано до коміту.
- tools/android-chrome-acceptance.mjs підготовлений і пройшов лише перевірку синтаксису. Не запускався; це планований синтетичний Android Chromium сценарій, не доказ реальних акаунтів, PWA installation, фізичного телефону чи production.

## Межі продукту

Цей крок не змінює Synera UI, не публікує сайт, не підтверджує iPhone/Safari, живий двосторонній цикл або платежі. Попередній push був заблокований; нових спроб push не виконано. Provider calls: 0, USD 0.

## Один наступний крок

Відновити щонайменше 10 GiB вільного C без видалення активних даних; після закриття зайвих програм перевірити RAM і запустити видимий емулятор з GPU host. Спочатку прийняти стабільний Android UI, потім вручну відкрити Chrome за участі користувача та виконати підготовлений локальний сценарій. Boot flag сам по собі не є PASS.
