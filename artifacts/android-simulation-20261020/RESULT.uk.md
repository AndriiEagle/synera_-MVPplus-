  ролями й межами. Початкове повідомлення чесно позначено як fixture.
- Окремий сервер симуляції без доступу до справжніх профілів, auth, SQL
  чи платежів. Приватний ключ запуску → HttpOnly cookie; exact Host/Origin,
  авторизований actor із cookie, окрема пара, послідовне атомарне збереження.
- Чинна модель Synera для п’яти режимів, редакцій і двох згод.
  Платний сценарій містить один результат виконавця. Текст перевіряє
  й приймає тільки отримувач; компенсація не видається за платіж.
- Мобільний UI, чернетки, журнал, експорт, manifest і service worker.
  API не потрапляє в offline cache. Без backend AI не симулюється підставними
  повідомленнями.
- Screenshot runner: фактичний PNG 390×844 → канонічний Token Monster →
  перевірене рішення → видима дія в тому самому UI → PNG після дії.
  Застаріла revision, чужий actor, STOP і дія поза екраном відхиляються.
  До передачі перевіряються контакти й схожі на ключі дані.
- Згода на провайдера прив’язана до конкретної пари. STOP очищує дозволи;
  запит у польоті завершує облік, але його пізню дію застосувати не можна.
- Спільний бюджет етапу: $6 максимум ($4 Flash, $1 GLM 5.3, $1 Argon).
  Receipt із невідомою вартістю блокує наступні платні виклики.

Попередні TA-01–04 залишено в base. Current/Atelier, реальний Neon gateway,
SQL та readiness flags цим етапом не змінювалися. Незакомічений оригінальний

## Перевірка

- Node **24.16.0**: **743 тести, 742 PASS, 0 FAIL, 1 SKIP**.
  SKIP — окремий disposable PostgreSQL run у цьому локальному запуску.
- Python: **3/3 PASS** для спільних бюджетів, невідомої вартості й
  канонічного відновлення receipt.
- Справжній локальний HTTP + Chromium: приватний вхід, 20 доступних ролей,
  дві окремі cookie-сесії, повний платний цикл, receiver-only acceptance,
  безпечний текст, чернетки й фокус, STOP.
- 320/390/1440 px і текст 200%: немає горизонтального переповнення;
  axe: **0 serious/critical**. [Знімки та browser receipt](browser/acceptance.json).
- Справжній PNG передано локальній ін’єкції моделі; відкладене рішення
  після STOP відхилено. **Це synthetic controller, не live vision PASS.**
- Build: **113 файлів, 112/112 hash/size збігаються**; не опублікований.
- Семантичний негативний контроль: видалення revision guard спричиняє FAIL.
- Зовнішнє **HTTPS через Quick Tunnel**: без cookie 401, exact-Origin
  відмова 403, приватний вхід, Secure/HttpOnly/SameSite cookie, no-store,
  20 учасників. Chromium у звичайному окремому профілі повернув
  `installabilityErrors: []`. [Receipt](HTTPS_ACCEPTANCE.json).
  Це перевірка браузером на комп’ютері, не встановлення на Android.

Виявлені й виправлені під час приймання дефекти:
згода іншої пари; гонка чернеток під час перемикання; недоступне з клавіатури
прокручування розмови; випадково розширена публічна видача старого
`simulation.mjs`. Останню усунуто винесенням незмінених даних персонажів;
існуючий тест вимоги 404 збережено, повний повтор пройдено.

UI створював окремий Codex worker gpt-6.1-sol/high. Прочитано його результат
і один окремий цільовий completion review; після цього координаторка
виконала незалежну від його fixtures перевірку реального HTTP/UI.
Це внутрішня модельна й програмна перевірка, не незалежна людська експертиза.

Другий окремий Codex reviewer знайшов дві гонки підготовки кадру:
STOP міг передувати новому виклику, а privacy scan — стосуватися старого
стану. До виправлення три керовані негативні сценарії дали FAIL
(STOP, зміна revision, приватна чернетка); чистий контроль — PASS.
Після виправлення **4/4 PASS**: три відмови відбуваються до provider invocation.
Reviewer самостійно повторив їх і завершив окремий follow-up як NO_CHANGE.
Перевіряються backend і DOM revision, видимі поля та фінальний STOP
без `await` до виклику. Скасування вже розпочатого запиту не обіцяється.

## Що лишилося до користування з телефона

1. **Сталий hostname** для наступних сеансів: вхід власника в Cloudflare
   вже підтверджено, але підключеного домену немає. Для першої перевірки
   працює тимчасовий Quick Tunnel лише до loopback-порту симулятора.
   Офіційний portable `cloudflared 2026.10.2` звірено з release SHA256;
   Windows service й autostart не встановлювалися.
2. **Канонічний облік GLM 429**: відновлений receipt або доказ від провайдера.
   Потім — обов’язковий GLM review та реальний image-input → UI action
   з identity/cost/hash receipts і незалежним прийманням.
3. **Фізичний Android**: встановлення, повторне відкриття, клавіатура,
   втрата мережі, STOP під час виклику й повний корисний цикл із живим AI.
4. Node 22 CI після push — перевірити конкретний commit у GitHub Actions.

Старий публічний сайт не оновлювався цим етапом. Публікація source у `main`
не є deploy або готовою Android-доставкою. Production SQL/JWT, backup/restore
і випробування з реальними людьми залишаються окремими воротами.

Найсильніший контраргумент: навіть коректні синтетичні співрозмовники можуть
створити відчуття користі без реальної взаємності й попиту. Тому результати
цього тесту приймаються як UX/технічні докази; висновки про клієнтів потребують
окремої добровільної людської когорти.
