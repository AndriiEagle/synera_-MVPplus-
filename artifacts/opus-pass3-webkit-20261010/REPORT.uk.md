## PostgreSQL 18: що саме доведено

[Receipt Opus](../opus-review-20261009/pass3/PG18_SQL_ACCEPTANCE.json) містить
18 стадій на loopback PostgreSQL **18.4**, identity shim, RED baseline,
70 full-stack ownership/consent oracle у двох порядках та mutation rejection.
У цьому проході незалежно звірено **12 source hashes** receipt із Git-блобами
прийнятого коду. PG18 тут повторно не встановлювався й не запускався.
Раніше прочитана production версія **18.6** — інша patch-версія і не приймання
живого JWT/Data API. SQL stack не змінений третім проходом, окрім сумісності
діагностичного locale query з `datlocale` / `daticulocale`.

## Три агентні задачі, дві паралельні хвилі

1. Незалежне read-only рев’ю Opus: source/consent/drafts/focus, гіпотеза перевірена
   фактичними координатами в браузерах.
2. Read-only пошук конкретної прогалини запуску: втрачений message retry UUID
   після reload. Ризик відтворено actual WebKit: два server rows замість одного.
3. Вузька реалізація recovery в existing `RealJourneyStore`; окреме приймання —
   [артефакти message reload](../message-reload-20261010/WORKER.uk.md).
   Остаточний результат цієї доробки та фінальний build мають окремий receipt.

Одночасно працювали максимум двоє дочірніх агентів; нових user-owned чатів,
router/queue/ledger/skill, hosted provider calls або фонового нагляду не створено.

## Системи та досвід людини

Це продуктовий стан, а не вимір емоцій: у цьому проході були тестові акаунти.
Нижче «має відчувати» — вимога до дизайну для перевірки з першими людьми.
Гормони, психологічна сумісність, залежність чи задоволеність не вимірювалися.
Повний історичний [27-system inventory](../product-status-20261004/STATUS.uk.md)
збережений; ця таблиця показує 15 робочих пакетів і поточні межі.

| Система / крок | Поточний стан | Що людина має відчувати; перевірювана умова |
|---|---|---|
| 1. Вхід, акаунт, дозволи | Локальні guards є; живий JWT і EN/DE entry/profile ще відкриті | Спокій і контроль: зрозуміло, хто бачить дані; нічого не стає публічним без вибору |
| 2. Give–Take / пошук | Двосторонні self-declared критерії та пояснення є локально; «іскра» не доведена | «Я бачу користь для обох»: конкретна причина рекомендації, можливість відмовитися |
| 3. Atlas / місце зустрічі | Карта/вибір профілю часткові; адреса погоджується двома; Google route URL є, embedded SDK та живі шари не прийняті | Орієнтація: зрозуміло, де й навіщо зустріч; приватна точна локація не розкривається мовчки |
| 4. Умови, приватний чат | Локальний шлях і guards прийняті; reload recovery — окремий фінальний receipt | Ясність і потік: одна редакція, дві згоди, без втрати наступної думки або випадкового дубля |
| 5. Фактичний результат | Evidence/check/спір/прийняття одержувачем локально є; живий результат ще не отриманий | Справедливість: видно, що саме прийнято й ким; система не видає заяву учасника за незалежну перевірку |
| 6. Android/iPhone PWA, дизайн | Current default, Atelier добровільний; WebKit/Chrome responsive є; OS install/keyboard/lifecycle не прийняті | Легкість: читабельно, кнопки доступні, фокус і чернетки збережені; встановлення без плутанини |
| 7. AI / голос | Є локальні/advisory компоненти; передовий live voice onboarding не активований | Допомога без тиску: AI пояснює дію й межу, не приймає згоди замість людини |
| 8. Triangle L | Same-device режим і окремі backend/SQL компоненти; живі 2–3 учасники/voice/video не прийняті | Рівна можливість висловитися; добровільні правила, видиме керування, без прихованого переписування слів |
| 9. Проєкт / команда | Двосторонній trial є; автоматичний пошук/набір ширшої команди не завершений | Посильний рух: конкретний внесок, наступна дія й право вийти без примусу |
| 10. Радари | Модулі/сценарії часткові; live sources/freshness/background notifications не прийняті | Релевантність: мало корисних сигналів із джерелом, частота під контролем людини |
| 11. Соціальні чернетки / інтеграції | Власний прийнятий внесок → редагована чернетка локально є; OAuth/публікація не активні | Гордість без вигадки: людина перевіряє текст і сама вирішує, що опублікувати |
| 12. Репутація | Механізми часткові; незалежне live reputation acceptance відсутнє | Довіра: зрозумілі підтверджені внески, можливість оскарження; кліки не прирівнюються до виконаної роботи |
| 13. Коворкінг / події | Сценарії часткові; жива широка координація й external integrations не прийняті | Належність і комфорт: місце/час обираються явно; мовчання не створює фінансового чи зустрічного зобов'язання |
| 14. Приватний архів / пам'ять | Plain/gzip export і viewer локально є; cloud backup/restore та міжпристроєва пам'ять відкриті | Володіння результатом: можна забрати точний текст; стиснення не називається шифруванням або доведеним 10× зменшенням LLM вартості |
| 15. Оплата / телеметрія / AI cost | Тимчасово безплатний пілот і цінова гіпотеза є; checkout/платні provider calls вимкнені | Прозорість: відома ціна й межі, ніяких неочікуваних списань або прихованого поведінкового стеження |

## Що відділяє код від виходу на ринок

1. **Безпечний live rollout:** точні schema/grants, guard 1a, recovery point/restore,
   вартість і новий pinned candidate; чинний дозвіл push не є production approval.
2. **Два справжні акаунти:** email/JWT → відхилене sender self-accept через HTTP
   (зафіксувати фактичний Neon статус для PT409) → дві згоди → чат → адреса →
   прийнятий результат → експорт. Лише за дозволом учасників, без підміни ботами.
3. **Фізичні Android та iPhone:** install, keyboard, поворот, background/return,
   offline/update. Desktop WebKit і емулятор, що завантажився, цього не доводять.
4. **Критичний шлях мовою когорти:** прийняти фактичний Opus EN/DE entry/profile,
   перевірити перехід у journey та зрозумілі правила/допомогу; native-language review.
5. **Операційне приймання:** перевірити на живому пілоті support, доступ/видалення,
   retention/recovery, інцидентні дії й реальні cost limits; контакти/код самі
   по собі не доводять виконання процедури.
6. **Перші 5–10 добровільних людей:** реальний корисний обмін, відмови/фідбек,
   вимір виконаного результату та зрозумілість ціни. Це gate першого пілота.
   Масовий запуск додатково потребує sustained distinct-user capacity/cost,
   а розширені Google/voice/L/OAuth можливості мають окремі capability gates.

## Межі запуску

PWA, OS keyboard/lifecycle, два живі JWT-акаунти, production schema/recovery,
provider voice/Google SDK/OAuth/payments і sustained capacity не прийняті.
